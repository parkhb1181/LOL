# PRD — GRANDSLAM 1v1 공 배틀 (Ball Battle)

| 항목 | 내용 |
|---|---|
| 버전 | v1.0 |
| 작성일 | 2026-06-14 |
| 상태 | 신규 기능 — 단계별 구현 |
| 소속 | GRANDSLAM 본체의 부가 기능 (`/battle` 페이지) |
| 브랜치 | `ball-battle` (격리 작업) |
| 목적 | **홍보 영상 양산** (재방문 약한 비타민 사이트의 신규 유입 엔진) |

---

## 0. 한 줄 정의

GRANDSLAM 선수 카드 2장을 골라 (예: 16 Faker vs 24 Chovy) OVR을 HP로 환산한 공 배틀을 자동 재생하고, 인트로 → 배틀 → 승자 발표까지 한 편의 세로 영상으로 뽑아 SNS에 뿌리는 **콘텐츠 양산 도구**.

---

## 1. 배경 & 목적

### 1.1 문제

- GRANDSLAM은 "한 번 해보는" **비타민형** 사이트 → 재방문율 낮음.
- 현재 유입 99%가 단일 커뮤니티(fmkorea) → 경로 편중 리스크.
- UGC는 트래픽 부족(일 ~100명)으로 불가 → **운영자가 직접 콘텐츠 공급**해야 함.

### 1.2 해결 — 영상 양산

- "공 배틀" 포맷은 틱톡/릴스/쇼츠에서 검증된 바이럴 형태 (ball_fight_korea 등).
- **카드를 그대로 사용** → 영상 자체가 GRANDSLAM 광고 (브랜딩 일관).
- **선수 조합 무한** → 콘텐츠 무한 생산 (Faker vs Chovy, 16 Faker vs 24 Faker 등).
- **논쟁적 매치업** → 댓글/공유 유발 ("이게 맞냐" = PRD 본체의 "레이팅 논쟁=콘텐츠"와 동일 동력).

### 1.3 왜 직접 만드나 (기존 도구 대비)

| | 기존 도구(ViralBalls 등) | 직접 개발 |
|---|---|---|
| 브랜딩 | 약함 | **카드 그대로** |
| 양산 후 자동화 | 수동 세팅 | **자동 매치업 생성 가능** |
| 링크 시너지 | 외부 도메인 | **grandslamlol.../battle** → 본체 유입 |

→ 영상에서 본체 게임으로 유입 연결이 목적이므로 **같은 도메인의 `/battle`**이어야 함.

---

## 2. 목표 · 비목표

### 2.1 목표

1. 선수 2명 → 자동 재생 배틀 → 한 편의 세로 영상으로 추출 가능.
2. 영상 전체에 사이트 링크 고정 (어느 프레임이 잘려도 출처 노출).
3. 매치업을 빠르게 갈아끼워 **하루에 여러 영상** 생산 가능한 워크플로.

### 2.2 성공 기준

- 매치업 세팅 → 영상 1편 추출까지 **2분 이내** (양산 효율).
- 영상이 세로(9:16)로 깔끔하게 녹화됨 (UI 군더더기 없음).
- 본체 게임(`/draft`, `/dex`, 결과)에 **회귀 0** (격리 성공).

### 2.3 비목표 (v1에서 안 함)

- **자동 영상 파일 export** (canvas→mp4). → 화면 녹화(OBS/폰)로 대체. 개발 복잡도 대비 효익 없음.
- 실제 게임 수준의 스킬 밸런스/전투 로직. → 연출 + 흉내 수준만.
- 멀티플레이/유저 대전.
- 선수별 개별 스킬 데이터. → 포지션/등급 단위로 묶음.
- 모바일 인터랙티브 최적화 (영상 추출용이지 플레이용이 아님).

## 3. 핵심 영상 구조 (최종 산출물)

```
[1. 인트로 — 약 2초]
  - 카드 2장 좌우 등장
  - 중앙 "VS"
  - 상단/하단: "16 FAKER vs 24 CHOVY"
  - 하단 고정: grandslamlol.vercel.app

[2. 배틀 — 본편 (가변)]
  - 사각 아레나에서 공 2개 충돌
  - OVR → HP, 충돌 시 HP 감소
  - 각 공: 이름 + HP바
  - 스킬 발동 시 이펙트 + 특수 데미지 (4단계)
  - 하단 고정: 링크 (계속)

[3. 승자 — 약 2초]
  - 이긴 선수 카드 확대/강조
  - "WINNER: 24 CHOVY"
  - 하단 고정: 링크
```

**불변 규칙**: 링크는 인트로·배틀·승자 **전 구간 하단 고정**. 영상이 어디서 잘려 공유돼도 출처가 항상 박힘.

---

## 4. 승부 로직

- 기본: **OVR 기반 HP** (예: OVR 99 → HP 300 등 스케일 환산).
- 충돌 데미지: 기본 데미지 + 약간의 랜덤 (매번 결과가 똑같지 않게).
- **스킬 적중 시 특수 데미지** (4단계): 일반 충돌보다 큰 데미지 + 이펙트.
- 결과는 **결정론적이지 않게** (같은 매치업도 돌릴 때마다 승자가 갈릴 수 있어야 콘텐츠 다양성 확보) — 단 OVR 높은 쪽이 통계적으로 유리.

> ⚠️ 밸런스 정교화는 비목표. "보기 재밌고, 가끔 이변이 나는" 수준이면 충분.

---

## 5. 스킬 정의 (4단계, 연출 중심)

선수가 수백 명이므로 **개별 스킬은 비현실적**. 다음 중 택1로 묶음:

| 방식 | 설명 | 난이도 |
|---|---|---|
| **포지션별** (권장) | TOP/JGL/MID/ADC/SUP 5종 이펙트 | 낮음 |
| 등급별 | OVR 구간별 이펙트 (99=황금 등) | 낮음 |
| 리그별 | LCK/LPL/LCS/LEC 색상 이펙트 | 낮음 |

- 스킬 = **비주얼 다양성 + 특수 데미지 트리거**. 실제 챔피언 메커니즘 재현 아님.
- 발동: 일정 간격 또는 충돌 N회마다 자동 발동 (유저 입력 없음 — 자동 재생이므로).

---

## 6. 단계별 로드맵 (구현 순서)

> **원칙: 각 단계 완성 → 로컬 확인 → 다음 단계. 한 번에 다 구현 금지.**

### 1단계 — 기본 골격 (토대)
- `/battle` 페이지, 사각 아레나, 공 2개(임시 원).
- 물리(벽 튕김 + 상호 충돌), 충돌 시 HP 감소, 승자 표시.
- 선수 하드코딩 2명, "재생" 버튼.

### 2단계 — 선수 데이터 연동
- 실제 선수 사진(R2) → 공 텍스처.
- OVR → HP 환산.
- 매치업 선택 UI (또는 랜덤 버튼).

### 3단계 — 영상 흐름 (산출물)
- 인트로(VS 카드) → 배틀 → 승자 카드 **자동 재생**.
- 세로 9:16 레이아웃.
- 링크 전 구간 고정.
- 녹화 친화 (UI 숨김 모드, 깔끔한 배경).

### 4단계 — 스킬/이펙트
- 포지션/등급별 이펙트.
- 스킬 적중 시 특수 데미지.

### 5단계 — 녹화 (개발 X)
- OBS 또는 폰 화면녹화로 영상 추출.
- 자동 export 기능은 만들지 않음.

## 7. 🔴 격리 규칙 (절대)

```
[작업 범위 — 여기만]
  app/battle/              ← 배틀 페이지
  components/battle/       ← 배틀 전용 컴포넌트
  lib/battle/ (필요 시)    ← 배틀 전용 로직

[절대 수정 금지 — import/읽기만]
  app/draft, app/dex, 결과 페이지, app/page(홈)
  components/PlayerCard 등 기존 공용
  선수 데이터(players) — 읽기만, 수정 X

[브랜치]
  ball-battle 에서 작업 → 완성·검증 후 main 머지
```

- 본체 게임 회귀가 발생하면 **즉시 중단**하고 격리 위반 지점 점검.
- 기존 컴포넌트를 "고쳐서" 재활용하지 말 것 → 배틀 전용으로 새로 만들거나 import만.

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 물리 구현이 까다로움 | 외부 라이브러리 허용, 1단계에서 토대 확정 |
| 여러 에이전트 동시 작업 시 충돌 | **파일 비중첩 분할** (물리/이펙트/UI/데이터 분리) |
| 본체 회귀 (드래프트에서 경험) | `/battle` + `battle/` 폴더 격리, 브랜치 |
| 자동 녹화 욕심 → 시간 낭비 | 녹화는 OBS로, 개발 안 함 (비목표 명시) |
| 스킬 데이터 노가다 | 포지션/등급 단위 묶음 (개별 X) |
| 영상 반응 불확실 | 1~3단계로 빠르게 최소 영상 → 반응 보고 4단계 투자 |

---

## 9. 철수/판단선

- 1~3단계로 **최소 영상**을 뽑아 반응 테스트.
- 반응 있음 → 4단계(스킬) + 양산 본격화.
- 반응 없음 → 본체 유지보수 모드로, 배틀은 보류 (격리되어 있어 본체 영향 0).

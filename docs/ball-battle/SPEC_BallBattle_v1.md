## 1단계 — 기본 골격

### 목표
공 2개가 사각 아레나에서 부딪히고 HP가 깎이며 승자가 나오는 최소 동작.

### 구현
- **라우트**: `app/battle/page.tsx`, 경로 `/battle`.
- **아레나**: 정사각 영역. 배경 단색(흰색 또는 어두운색). 테두리 표시.
- **공 2개**:
  - 원형. 1단계는 사진 없이 임시(단색 + 이니셜 텍스트).
  - 각 공에 `x, y, vx, vy, radius, hp, maxHp, name` 상태.
- **물리**:
  - `requestAnimationFrame` 루프 또는 `<canvas>`.
  - 매 프레임 위치 갱신(`x += vx`).
  - **벽 충돌**: 아레나 경계 도달 시 속도 반사(`vx = -vx`).
  - **공-공 충돌**: 두 원의 중심 거리 < 두 반지름 합이면 충돌. 속도 교환/반사(간단한 탄성 충돌).
- **데미지**: 공-공 충돌 발생 시 양쪽(또는 충돌 측) HP 감소. 데미지 = 기본값 + 소량 랜덤.
- **HP바**: 각 공 근처(위 또는 아래)에 이름 + `current/max` 바. 색은 초록(높음)→빨강(낮음) 가능(선택).
- **승패**: 한쪽 HP ≤ 0 → 루프 정지 → "WINNER: {이름}" 표시.
- **재생 버튼**: 누르면 배틀 시작(초기화 후 루프 시작).
- **선수**: 하드코딩 2명 (예: `{name:'FAKER', maxHp:300}`, `{name:'CHOVY', maxHp:250}`).

### 기술 메모
- 물리 라이브러리(matter.js 등) 사용 가능. 단 의존성 추가 시 package.json에만 반영(전역 영향 X).
- 캔버스 권장(공/충돌/이펙트 확장 용이). DOM 방식도 허용하나 후속 단계(이펙트) 고려 시 캔버스가 유리.

### 향후 염두 (1단계서 구현 X, 구조만)
- 인트로→배틀→승자 자동 재생, 세로 9:16, 링크 고정, 화면녹화 추출.
- → 1단계 코드를 "단계(phase) 전환" 구조로 짜두면 3단계에서 인트로/승자 얹기 쉬움. (예: `phase: 'intro' | 'battle' | 'result'` 상태를 미리 염두)

### ✅ 완료 조건
- [ ] `/battle` 진입 시 아레나 + 공 2개 표시.
- [ ] 재생 시 공이 움직이고 벽/서로 충돌.
- [ ] 충돌 시 HP 감소가 HP바에 반영.
- [ ] 한쪽 HP 0 → 승자 표시.
- [ ] `npm run build` 통과.
- [ ] `/draft`, `/dex` 정상 (회귀 0).

## 2단계 — 선수 데이터 연동

### 목표
임시 공을 실제 선수(사진 + OVR)로 교체.

### 구현
- 기존 선수 데이터에서 **import**(읽기 전용)하여 선수 목록 확보.
- **사진**: 선수 이미지(R2 URL)를 공 원형 안에 텍스처/클립으로 표시(원형 마스크).
- **OVR → HP 환산**: 단조 함수로 매핑(예: `hp = OVR * k` 또는 구간 환산). OVR 높을수록 HP 큼.
- **매치업 지정**:
  - 최소: 두 선수를 코드/드롭다운으로 선택.
  - 권장: "랜덤 매치업" 버튼(무작위 2명) — 양산 시 빠름.
  - 선수 식별은 본체의 slug/id 규칙을 따름(이름 공백 처리 주의).
- 이름 표기: 영상 표기를 위해 "{연도2자리} {닉네임}" 형태 지원(예: `16 FAKER`). 연도 데이터가 있으면 활용.

### ✅ 완료 조건
- [ ] 공 안에 실제 선수 사진 표시(원형).
- [ ] HP가 OVR 기반으로 설정됨.
- [ ] 매치업 선택(또는 랜덤) 동작.
- [ ] `npm run build` 통과 + 본체 회귀 0.

## 3단계 — 영상 흐름 (핵심 산출물)

### 목표
인트로 → 배틀 → 승자까지 **자동 재생되는 한 편의 영상** + 링크 고정 + 세로 비율.

### 구현
- **phase 상태 머신**: `intro → battle → result` 자동 전환.
- **인트로(약 2초)**:
  - 카드 2장 좌우 등장(본체 카드 디자인 참고하되 배틀 전용으로 구현, 기존 PlayerCard 수정 금지).
  - 중앙 "VS".
  - 매치업 텍스트: "16 FAKER  vs  24 CHOVY".
- **배틀**: 2단계 결과 재생.
- **승자(약 2초)**:
  - 이긴 선수 카드 확대/강조.
  - "WINNER: 24 CHOVY".
- **링크 고정**: 모든 phase 하단에 `grandslamlol.vercel.app` 고정 오버레이.
- **세로 레이아웃**: 9:16 비율 컨테이너(예: 1080×1920 기준 스케일). 틱톡/릴스/쇼츠 대응.
- **녹화 친화 모드**:
  - 재생 버튼/선택 UI 등 **조작 요소를 녹화 화면에서 숨기는** 토글 또는 풀스크린 재생.
  - 배경 군더더기 제거(깔끔).
  - 자동 재생: 한 번 트리거하면 인트로~승자까지 끊김 없이 진행.

### 비목표 재확인
- 영상 파일 자동 생성(mp4 export) **하지 않음**. OBS/폰 화면녹화로 추출.

### ✅ 완료 조건
- [ ] 트리거 1회로 인트로→배틀→승자 자동 진행.
- [ ] 링크가 전 구간 하단 고정.
- [ ] 9:16 세로 레이아웃으로 깔끔하게 표시.
- [ ] 녹화 시 조작 UI가 안 보이는 모드 존재.
- [ ] `npm run build` 통과 + 본체 회귀 0.

## 4단계 — 스킬 / 이펙트

### 목표
부딪힘만 반복되지 않게, 스킬 이펙트 + 적중 시 특수 데미지.

### 구현
- **스킬 묶음 방식 택1**(PRD §5): 포지션별(권장) / 등급별 / 리그별.
  - 포지션별: TOP/JGL/MID/ADC/SUP 각 1종 이펙트.
- **발동**: 자동(일정 간격 또는 충돌 N회마다). 유저 입력 없음(자동 재생).
- **이펙트**: 캔버스 파티클/도형 애니메이션(투사체, 폭발, 오라 등). 챔피언 실제 스킬 재현 아님.
- **특수 데미지**: 스킬 적중 시 일반 충돌보다 큰 데미지 + 시각 강조(피격 플래시 등).
- 데이터: `lib/battle/skills.ts`에 묶음 단위로 정의(개별 선수 X).

### ✅ 완료 조건
- [ ] 배틀 중 스킬 이펙트가 발동/표시됨.
- [ ] 스킬 적중 시 특수 데미지 적용.
- [ ] `npm run build` 통과 + 본체 회귀 0.

## 병렬 작업(에이전트 여러 개) 분할 가이드

여러 에이전트를 동시에 쓸 경우 **파일이 겹치지 않게** 분할한다. (본체 드래프트에서 동시 수정으로 회귀가 반복된 전례)

| 에이전트 | 담당 파일 | 비고 |
|---|---|---|
| A | `lib/battle/physics.ts` | 충돌/이동 로직 |
| B | `lib/battle/skills.ts` | 스킬 데이터/발동 규칙 |
| C | `components/battle/Arena.tsx` | 아레나/캔버스 렌더 |
| D | `components/battle/BattleHUD.tsx` | 이름/HP바/링크 오버레이 |
| E | `app/battle/page.tsx` | phase 머신/조립 |

- 인터페이스(타입)를 먼저 합의하고 각자 자기 파일만 수정.
- 통합(조립)은 E 담당이 마지막에 수행.
- **단, 1단계는 구조가 작으므로 1개 에이전트로 끝내는 편이 안전.** 분할은 3~4단계처럼 커질 때 적용.
